# 交換禮物遊戲階段（exchange）設計規格

> 沙盒設計中：`python sandbox_app.py` → `http://localhost:8478/sandbox/exchange.html`
> 與正式畫面、正式 DB 分開；驗收後才合併進 `game.js` / `game_server.py` / 正式 DB。
> 本檔隨討論逐項更新，標「待討論」的項目尚未定案。

## 1. 進入條件

- 管理者把活動階段切到「交換禮物遊戲」（`settings.stage = exchange`）後，所有人的畫面進入本階段

## 2. 畫面：聚光燈輪轉（2026-11-11）

- **不再顯示禮物牆**（26 格跳舞的禮物都拿掉）
- 舞台中央一盞**聚光燈**，燈下是**目前抽到的禮物**（放大）
- 聚光燈**右邊**：待命中、下一個要抽的禮物
- 聚光燈**左邊**：剛剛抽過的禮物
- 換下一個時整排**往左輪轉**：
  - 右邊待命的 → 滑進聚光燈下並放大
  - 聚光燈下的 → 滑到左邊並縮小
  - 原本左邊的 → 滑出畫面左側
  - 新的待命禮物 → 從畫面右側滑進來
- 每個禮物下方顯示標籤牌（標籤配色）與「{動物}的禮物」
- 聚光燈依整體風格：**硬邊、平塗、無漸層、無發光**；以半透明奶油白的光錐＋地面光圈表現，聚光燈以外的牆面壓暗一階（仍是木牆，不是深色虛空）

## 2-1. 抽獎順序（2026-11-11）

- **隨機決定，不用禮物牆順序**；存在 `players.draw_order`（0 起算，migration `m004_add_draw_order`）
- **切進交換禮物遊戲時自動洗牌**：管理頁把階段從別的階段切到「交換禮物遊戲」那一刻，
  以切換時間 `yyyymmddhhmm`（本機時間）當種子洗牌，種子記在 `settings.draw_seed`
  - 退回上一階段再切進來 → 時間不同 → 新的順序
  - 已經在交換禮物遊戲時再按一次送出 → 不重洗
  - 同一分鐘內退回又切進來 → 種子相同 → 順序相同
  - 同一個種子必得同一個順序（依 id 排好再洗），事後可由 `draw_seed` 還原
- 正式庫與測試庫**各自獨立洗牌**，測試庫不沿用正式庫的順序（建測試庫時以當下時間另洗一次）
- 正式庫的順序**不公開**：程式只印數量，不印順序與種子；正式 server 沒有任何讀順序的 API
  （`/api/draw_order` 只存在沙盒的 `SandboxHandler`，沙盒頁面會顯示洗牌碼方便驗收）
- 手動工具（平常不需要）：`python tools/shuffle_draw_order.py`（預設正式庫；已有順序就不動，
  `--force` 重洗，`--seed` 指定種子；寫入前自動備份成 `game.db.bak-時間`）
- 之後新增的禮物沒有順序，排在最後
- 正式庫 2026-11-11 先手動洗過一次（備份 `game.db.bak-20261111-115302`）；
  正式版合併後，切進交換禮物遊戲時會以切換時間重洗、取代這次的順序

## 2-2. 禮物講話框與描述修改（2026-11-11）

- 禮物轉到聚光燈下、**停好之後**，頭上彈出講話框，內容是這份禮物的描述；輪轉中講話框收起，下一份停好再彈出
- 講話框是疊在舞台上的 HTML（文字清楚、手機字級自動縮放），奶油白底＋深棕描邊＋硬邊投影＋三角尾巴，從尾巴尖端彈出放大
- **描述從「交換禮物遊戲」起對所有人公開**（`models.DESCRIPTION_PUBLIC_STAGES = exchange, feast`，`/api/state` 每份禮物帶 `description`）；「公布標籤」階段仍只有寫的人看得到
- 其他人只能看；**禮物主人**在舞台下方「我的禮物描述」隨時修改（交換禮物遊戲階段可改，50 字以內），
  按送出就寫入資料庫，大家的講話框在下次輪詢（約 3 秒）換成新描述；正在聚光燈下時只換字、不重新彈出
- 修改區只顯示給有認領禮物的人，內容是自己的描述；正在打字時輪詢不會蓋掉輸入框
- 沙盒 DB 裡還沒寫描述的禮物會自動填上「（測試）…」範例描述（只在沙盒，`build_sandbox_db.fill_sample_descriptions`）

## 2-3. 回合、候選人與爭奪（2026-11-11）

- **管理者按「開始」**後，聚光燈依抽獎順序一份一份來；每份禮物倒數 **3 分鐘**（`cms.EXCHANGE_ROUND_SEC = 180`），時間到自動換下一份。「下一個／重來」已拿掉
- 每份禮物上場時，從「**還沒獲得禮物、且不是這份禮物主人**」的人中隨機抽一位**候選人**（暫定在他名下）
- 其他還沒獲得禮物的人可以按「**加入爭奪禮物**」，花 1 張**搶奪券**；倒數結束前按「退出爭奪」會退還
  - 每人初始 5 張（`START_TICKETS`）；候選人以外最多 5 位挑戰者（`MAX_CHALLENGERS`）
  - 不能加入：禮物主人、候選人、已獲得禮物、券用完、名額已滿（畫面顯示原因）
  - 畫面顯示爭奪人數，以及「一起爭奪的人」名單（依加入順序，自己那一格標粉紅）
- 倒數結束：候選人＋挑戰者 **2 人以上 → 進小遊戲 PK**（見 2-4）；只有 1 人 → 直接給他；沒人可抽 → 沒有人。結算時還在名單上的挑戰者，券不退
- 得主記在禮物那一列的 `players.winner_id`；已獲得禮物的人不會再被抽成候選人、也不能再爭奪
- 「誰拿到了」清單公開所有已結算的禮物與得主（小遊戲決定的可展開看排名）；沒進小遊戲的回合結束時，舞台中央跳出「{動物}的禮物 → {得主}」
- 伺服器時間為準：回合推進不靠背景執行緒，每次有人讀狀態或動作時結算過期回合，下一回合從上一回合截止時間起算（沒人連線也會照時間表追上）
- **重新切進交換禮物遊戲＝整局重來**（順序重洗、得主與回合清空、券重設 5 張）
- DB：migration `m006_add_exchange`（`players.tickets / winner_id / won_at`、`exchange_rounds`、`exchange_challengers`）
- API（正式 server 也有）：`GET /api/exchange`、`POST /api/exchange/start`（管理者）、`/api/exchange/join`、`/api/exchange/withdraw`
- 沙盒測試可縮短倒數：`python sandbox_app.py --round-sec 30`

## 2-4. 小遊戲：丟石頭搶禮物（2026-11-11）

**時間軸**：倒數 3 分鐘 → 準備 15 秒（前 12 秒看玩法說明、最後 3-2-1）→ 遊戲最多 2 分鐘（120 秒）→ 公布 5 秒 → 聚光燈才換下一份（`GAME_PREP_SEC / GAME_SEC / GAME_REVEAL_SEC`）

**規則**
- 俯視地圖 32×20 格（不是迷宮）：外圍紅磚牆，中間有聖誕樹、雪人、禮物堆、中央磚塊當掩護；6 個出生點分散在四周
- 每人 5 滴血（`GAME_HP`）；操作**只支援電腦**：WASD／方向鍵移動；**按住空白鍵蓄力、放開丟石頭**，朝面向的方向，可以邊走邊蓄
- 地上會隨機生成：石頭（手上最多 3 顆，**要先撿石頭才能攻擊**）、愛心補血（+1，血滿不撿）；走過去自動撿。開場地上 10 顆石頭，之後約每 1.5 秒生一樣，上限石頭 12／補血 2。**地上不生禮物**
- **黑色怪物**（禮物唯一來源）：開打 5 秒出現第一隻，場上最多 2 隻（`MONSTER_MAX`）；石頭**打中一次就在旁邊掉一個禮物**，打 3 下（`MONSTER_HP`）消失，約 6 秒後補一隻
  - 怪物會去**吃地上的石頭補火**（最多存 3 發），朝 8 方向射線上、7 格內的玩家**噴火**（冷卻 2 秒），火打中扣 1 血，跟石頭一樣只是外觀是火；火不傷怪物
  - 沒火時找石頭吃，有火時靠近最近的玩家（3 格內停下）；頭上血條、腳下火苗＝存了幾發火，被打中閃白
- **參賽者沒有操作就站著不動**（不會有機器人代打）
- **被打中掉禮物**：身上有禮物的人被石頭或火打中（扣血那一下），旁邊掉出 1 個禮物；**原主人 10 秒內撿不回來**（`DROP_LOCK_SEC`），其他人可以馬上撿。原主人畫面上那份禮物半透明並顯示剩幾秒；無敵時間內被打中不扣血也不掉
- 蓄力最多 1 秒（`CHARGE_SEC`）：力道 0~1 決定射程 3→12 格、速度 9→15 格／秒；蓄力中腳下有力量條（蓄滿變粉紅），前方虛線標出會飛到哪（撞牆截斷）
- 石頭：冷卻 0.4 秒，撞到障礙物消失；打中扣 1 血，被打中後 0.6 秒無敵（閃爍）；不會打到自己
- 沒血就淘汰（變灰、改看直播）
- **勝負**：只剩 1 人活著 → 提早結束、他獲勝；時間到 → 活著的人比禮物數 → 血量 → 都同分就隨機。淘汰的人禮物再多也不能贏。最後幾個人同時陣亡 → 在他們之中照同樣規則比
- 結果寫進 `exchange_rounds.game_result`（排名 JSON），`resolved_by = 'game'`，得主寫進禮物的 `winner_id`

**網路設計（避免卡頓）**：平常的畫面都在本機跑，只有「砸中扣血、撿到東西、勝負」以伺服器為準
- 對戰整場只在伺服器**記憶體**（`minigame.py` 的 `StoneBattle`），遊戲中不讀寫 DB（正式 DB 在網路磁碟上）；token 有快取；HTTP 保持連線（keep-alive）
- **自己**：本機移動、本機丟出石頭（立刻飛出去）、走到東西上就先撿起來（東西先消失、數字先加）；每 50ms 把位置回報伺服器（`POST /api/minigame/input`，帶遞增 `seq`），按空白鍵立刻多送一次
  - 伺服器用「移動額度」檢查速度：額度以速度×1.3 累積、最多存 1 秒份，請求因網路抖動擠在一起到達也不會被誤判超速；晚到的舊回報（`seq` 較小）位置不採用
  - 兩次回報之間走過的路徑上的東西也算撿到，跟玩家在畫面上看到的一致
  - 伺服器真的拉回時（作弊或穿牆）位置用滑的修正，不會瞬間跳
  - 先撿起來但伺服器沒確認（被別人先拿走），0.8 秒內東西放回、數字退回
- **別人**：固定晚 0.12 秒播放，在前後兩份伺服器畫面之間內插；別人的石頭依速度外插。網路抖動也不會停頓或跳格
- **被砸中**：伺服器一確認就畫面閃紅、震動、頭上跳 -1；別人被砸中也會在畫面上跳 -1 與火花
- 丟石頭冷卻伺服器端寬容 0.1 秒，玩家端看到丟出去的石頭伺服器一定會算
- 小遊戲進行中，被蓋住的聚光燈舞台暫停重畫；地圖只畫一次，之後每幀直接貼上
- **觀眾（延遲直播）**：每 1 秒拉一次（`GET /api/minigame/watch?since=`），伺服器每 0.2 秒存一格、保留 4 秒；畫面延遲 1.5 秒播放並內插，左上角標「直播（延遲約 1.5 秒）」
- 實測：6 位參賽者每 50ms 回報＋20 位觀眾每秒 1 次（約每秒 138 個請求）→ 操作回應中位數 0.6ms、p95 1.2ms，遊戲中被拉回 0 次；網路延遲 10~150ms 隨機（81 次順序顛倒）模擬 400 次回報，被拉回 0 次
- 模擬一樣不用背景執行緒：每次有請求就以每秒 20 步把時間補到現在
- 伺服器在遊戲中重開 → 記憶體裡的對戰不見，該回合**立刻改用隨機**在候選人＋挑戰者中決定（`resolved_by = 'random'`），流程不卡住
- DB：migration `m007_add_minigame`（`exchange_rounds.game_epoch`、`game_result`；`status` 多 `game`）
- API：`GET /api/minigame/map`（地圖與移動參數）、`POST /api/minigame/input`、`GET /api/minigame/watch?since=`；`/api/exchange` 的回合多了 `phase`（contest / prep / play / reveal）、`participants`、`play_start / play_end / finished_at / reveal_end / ranking`，`me.in_game`

## 4. 沙盒驗收用的操作（只在沙盒）

- `python sandbox_app.py --round-sec 30 --game-sec 30`：倒數、小遊戲都縮短成 30 秒（機器人代打已拿掉：沒操作的參賽者就站著）
- 沙盒首頁 `http://localhost:8478/` 會夾帶 `static/sandbox/sandbox_bridge.js`（只有 `sandbox_app.py` 會夾，正式 server 不會）：
  登入後或管理頁切階段時，只要階段是「交換禮物遊戲」，就把登入 token 交給聚光燈頁（sessionStorage，讀完即刪）並自動跳過去
- 在聚光燈頁時，階段被切走就自動回首頁（首頁不記登入，要重新登入）
- 正式版 `game.js` 尚未接上聚光燈舞台，合併時再處理
